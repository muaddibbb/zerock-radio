## How it works
1. SHOW_SCHEDULE (358-392) = weekly slots; `name` keys the _WP_* maps (87-238); `_WP_SLUGS`/`_SHOW_DURATIONS_H` (4897, 4931) keyed by `key`.
2. schedule.json = queue. load/save_schedule (491-523): atomic (tmp, fsync, os.replace); read-modify-write under `_schedule_lock`.
3. api_add_show (5877) saves, replaces any untriggered entry for the slot, appends primary + paired rerun; starts `_move_to_nas`, then `_upload_and_mark_done` once `_upload_time_reached`.
4. `_upload_and_mark_done` (2128) -> `_do_podbean_wp_upload` (1914) -> POST to uploader on 114; `_verify_and_fix_wp_post` after 60s sleep; then WhatsApp notify.
5. scheduler_loop (2985) every 15s: triggers entries in window -600s..+45s (up to 6h late with resume), queues reruns, retries uploads, merge-saves only its own field deltas, then `_check_auto_reruns`, `_check_wp_posts`, file cleanup.
6. `_check_auto_reruns` (2651): at T-60 min a visible, non-excluded slot with no upload gets a placeholder; a thread downloads a RANDOM past Podbean episode whose title contains the show name (`random_choice=True`, 1624-1646). CLAUDE.md says "latest" (WRONG, fix doc).
7. api_reschedule_show (6180) moves one entry and shifts upload_time. 8. api_delete_show (6400) removes entry + its file_path.
9. All datetimes are naive server-local; no TZ in the service file.
